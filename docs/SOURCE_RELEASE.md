# Source release: October 20, 2026

This is the first public source release of the existing Python/React reference
implementation. It publishes existing work, not ninety days of reconstructed
feature history. The separate local learning rebuild is not replaced by this
release and no exercise is marked complete by publication.

## What is included

- Python control API, host authorization, durable worker and bounded repair graph.
- React Studio, optional illustrative 3D view and frontend checks.
- PostgreSQL migrations, owned sample apps, independent PDF checks and restricted
  candidate runner.
- Dependency manifests and lock/constraint files, local Compose configurations,
  MIT License, tests, reproducible experiment scripts and selected dated evidence.
- Failed experiment summaries as well as successful ones. A failed live model
  patch is not replaced by a later manual or synthetic success.

The repository's existing README history and original tenant-policy commit remain
ancestors of this release. The current application uses `src/ownstack`, rather
than the earlier root-level learning package. Their different policy interfaces
are successive implementations, not interchangeable modules.

## Historical evidence

The README's test counts and measurements describe recorded local runs on their
dated revisions. They are not freshly executed CI, a new deployment, an independent
fresh clone, or certification of the published tree.

An October 19 static comparison found the October 18 final security report still
matched its 47 canonical-text source bindings and six raw-file boundary bindings.
Those digest formats differ. The older graph r3 report has one changed raw binding
(`src/ownstack/repair.py`); its latency result describes the older revision.
The older offline-gaps report has three changed bindings
(`scripts/run_offline_demo.py`, `compose.rehearsal.yaml`,
`tests/test_offline_rehearsal.py`). The operations report also predates changes to
`src/ownstack/auth.py`, `scripts/rehearse_postgres_backup.py` and the learning plan.
Original report hashes and failures have not been rewritten to imply a rerun.

The graph comparison is 16 authored cases, two engines and three repetitions:
96 executions and 48 paired outcomes, not 96 unique scenarios. Its local p95
was slower than the simpler controller. Saved live PDF failures and the subsequent
assisted manual-path correction remain distinct. See [the case study](CASE_STUDY.md),
[validation](VALIDATION.md), [security hardening](SECURITY_HARDENING.md) and
[model usage](NVIDIA_NEBIUS_USAGE.md).

## Withheld artifacts

Credentials, runtime databases, proof exports, database dumps, private career and
learning records, internal handoffs, caches, installed dependencies, raw diagnostic
logs, JUnit XML and unreviewed screenshots are not part of this source publication.
Original local artifacts and failed runs are retained privately, not deleted.
Some dated reports refer to those original local paths. A reference to such a path
does not mean the underlying artifact is downloadable from GitHub. Selected JSON
summaries are published; unavailable raw diagnostics are not independent public
proof.

One public UI report uses a product-neutral browser runtime label; its outcomes,
measurements and source hashes are unchanged. The original report is retained
locally. Material coding-assistance provenance remains disclosed in the case study
and draft submission fields; no additional contributor identities are added.

Internal handoff references in older documentation are historical context. Public
entry points are [architecture](ARCHITECTURE.md), [security](SECURITY_HARDENING.md),
[validation](VALIDATION.md), [deployment](DEPLOYMENT.md) and this release note.
The daily plan is a public curriculum, not evidence of personal completion.

The existing CI configuration is included as an inactive example at
`docs/examples/ci.yml`, not under `.github/workflows/`. Automatic CI workflows
are intentionally not enabled in this release. Publishing
source does not authorize scheduled jobs, benchmarks, image builds, inference,
hosting or deployment. Reproduction commands are documented for explicit local
use; none of the old result counts should be presented as a green CI badge.

## Safety and open gates

Publication checks on October 20 used existing installed dependencies with empty
provider credentials and a zero live-call cap. Fifteen focused policy, packaging,
submission-inventory and curriculum tests pass. The first check had three failing
curriculum tests because the withheld automatic workflow was still referenced;
the configuration is now an inactive documentation example and the reference is
corrected. No application logic was changed by this publication pass. This is not
a new full-suite, frontend build, full-stack experiment or fresh dependency install.
Whitespace checking also reports three historical performance-report EOF blanks
and a generated initial-migration docstring's trailing space. Those existing
artifacts are retained byte-for-byte rather than rewritten during publication.

Use the README's explicit AI-off environment with zero live-call cap. The original
ten-call allowance is exhausted. A new clone or database does not renew it.
Demo identities and template passwords are synthetic local fixtures only; never
expose the default stack to the public internet.

The candidate runner shares a Linux kernel and reuses its supervisor. Independent
escape review, stronger per-job isolation, production identity/TLS operation,
customer validation, public hosted demo/video and final submission remain open.
Publishing this implementation does not close those gates.
