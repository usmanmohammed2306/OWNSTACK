### Models and variant choice

Used `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` for bounded interpretation through
Token Factory. Two interpretations were accepted; one drove actual approved
Atlas access, Nova denial and revoke. Used
`nvidia/nemotron-3-super-120b-a12b` for a stronger bounded PDF-patch attempt.
It failed independent syntax checks. In two predeclared routing cases per model,
each matched 2/2; Nano mean 1,179 ms, Super 1,857.5 ms. This small sample supports
further evaluation, not a general ranking or always-largest policy.

### Output quality: required 1-10 rating and explanation

**Owner rating required.** Factual context: bounded routing worked in the small
synthetic set. Code was not release-ready: Nano 0/3 usable drafts, Super 0/1
passing patches. Independent checks and AI-off correction were essential.
The coding assistant's correction is not Nemotron output.

### Fine-tuning, prompting or out of the box

No fine-tuning. Server-side bounded instructions and structured JSON are
validated before accepting a route. Host policy retains scope/duration authority.
Patch generation receives an owned single-file context. The host fixes the
path, original anchor and verifier command. The model cannot grant access,
author arbitrary shell commands or deploy.

### Comparison with other models

Nano and Super matched 2/2 routes each on the same newly worded, predeclared
cases, versus 1/2 for a kind-only baseline. Nano's mean latency and returned-
usage estimate were lower in those four calls. No other-model head-to-head or
statistically meaningful quality comparison was run. Failed-draft billing is
not reconciled.

operating a GPU deployment. Model ID, returned usage and measured latency are
saved with attempts. The interpretation becomes a proposal, not authority.
No AI Cloud GPU instance, Serverless Endpoint/Job, autoscaling or hosted Nebius
deployment is claimed. Current runtime is AI-off with the allowance exhausted.
