# OwnStack product hypothesis

OwnStack is the independent Nebius product. Relief is a separate Amazon product and is not modified by this implementation. Earlier shared-submission strategy is superseded; this new repository does not delete its history.

Buyer hypothesis: a B2B SaaS engineering/product team pays to fulfill legitimate customer-specific needs without maintaining permanent custom forks. This is unvalidated. User roles are tenant admin, contractor, engineer and product owner. The demo has Atlas and Nova synthetic tenants, not real customers.

Core outcome: an authenticated Atlas admin approves an exact host-derived temporary read-only grant. The host enforces it for Atlas only, denies Nova, and checks expiry/revoke on every read. An unsupported PDF feature becomes an engineering work item with exact diff, independent checks and a human manual-release decision. Convergence aggregates repeated needs without sharing request text or automatically promoting a variation.

October 9: Convergence separates request counts from variation-attributed host
authorization observations. Previews and role reads do not count as variation
use. Owner decisions require an entered rationale in Studio. These remain lab
signals, including retry traffic, not distinct humans, delivery confirmation or
validated buyer demand. Tenant-private proof export supports inspection rather
than claiming cryptographic attestation or deployment.

Complexity comes from enforcement and evidence, not more screens: contract scope, preview parity, state/revision fences, durable retries, model failure, isolated checks and human control. The current PDF fixture is deliberately small. Extending to arbitrary repositories or many contracts before validating this boundary would increase risk faster than evidence.

Compare against a simple feature-flag/manual process. Measure engineer touches, turnaround time, mistakes, rollback time and retained forks on the same actual request. The ten-case route baseline is only a development check, not that commercial comparison. See `FEEDBACK.md`, `UNPROVEN.md` and `SUBMISSION.md`.

October 13 evidence update: the offline compatibility lab now compares both owned
hosts with a competent shared-feature-flag baseline. All twenty measured effects
match; the baseline ties OwnStack's one-adapter edit on the selected upgrade.
OwnStack has not demonstrated a speed or maintenance advantage over that baseline.
The product hypothesis therefore depends on whether explicit approval, expiry,
evidence and variation lifecycle reduce real-team work or risk. Test that with the
team's actual request before adding more contracts. Durable repair is an engineering
control, not evidence that AI successfully solves arbitrary feature requests.
